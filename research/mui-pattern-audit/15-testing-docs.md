# MUI testing, documentation, manifest, and tooling audit

Audit date: 2026-09-13. The graph was queried first (`graft map`, then targeted `graft ask`); the graph covers 37 source files but also indexes the research notes, so the test tally below was counted from the actual `crates/` and `packages/` trees. No repository files were changed.

## Current baseline and strengths

The workspace has 11 Rust members, uses resolver 2, and declares edition 2021 centrally (`Cargo.toml:1-20`). The authoritative `cargo test --workspace --locked -- --list` inventory reports 148 ordinary test cases (145 active and 3 ignored) plus 8 doctests (5 active and 3 ignored), or 156 entries total. A source scan reconciles to 145 colocated ordinary `#[test]` cases and three ignored preview integration tests. Tests are mostly colocated unit tests, with `crates/mui-preview/tests/` providing the only standalone integration-test directory. This is a sensible split for private geometry/state invariants and a native gallery boundary, but it leaves most reusable crates without downstream-style integration tests.

Several tests express real contracts well. Scene resolution checks cycle rejection and transactional commit behavior (`crates/mui-core/src/scene.rs:523-591`); input tests cover winding holes, paint order, capture, click-versus-drag, pointer loss, and custom thresholds (`crates/mui-input/src/tests.rs:71-280`); preview tests compare painted paths with hit geometry on a 64×64 grid (`crates/mui-preview/src/main.rs:540-633`). The GPU resize test is explicitly ignored with a reason and documents its command (`crates/mui-preview/tests/render_resize.rs:1-15,119-150`), while timing tests are separately marked as measurements (`crates/mui-preview/tests/frame_cost.rs:1-7,22-24`). Those are good boundaries: deterministic behavior stays in the default gate, hardware and benchmark work is opt-in.

The facade deliberately turns the README into doctests (`crates/mui/src/lib.rs:19-27`). The parent baseline reports `cargo test --workspace --locked` passing with 8 doctest entries (5 active and 3 ignored), alongside the 148 ordinary test cases. `cargo test` already runs active doctests; `cargo test --doc` is a focused diagnostic, not a second mandatory gate. `rustfmt`, workspace Clippy with warnings denied, the library WASM check, TypeScript compilation, generated-Rust parity, and the demo also passed in the baseline session. I additionally ran `cargo test -p mui --features egui --locked --offline`; that targeted package check passed with four active README doctests and three intentionally ignored snippets.

The local gate is clear and fail-fast (`tools/verify.sh:1-24`): formatting, native tests, Clippy, a WASM target check, `npm ci`, strict TypeScript compilation, generated-Rust parity, and a demo run. TypeScript uses `strict`, declarations, and `noEmitOnError` (`packages/mui-ts/tsconfig.json:1-13`), and `npm ci` is backed by a committed lockfile (`packages/mui-ts/package-lock.json:1-27`). The generated output is compared rather than merely compiled (`tools/verify.sh:18-23`), which is a strong reproducibility check.

## Findings

| Severity | Evidence and failure/coverage gap | Recommendation |
|---|---|---|
| Medium | The repository has no `.github/` workflow or other remote CI configuration. The only repeatable gate is a developer-local script (`tools/verify.sh:1-24`), and the README tells users to run it locally (`README.md:449-457`). A green local run does not protect merges, releases, or contributions on a clean machine. | Add a CI workflow that runs locked fmt, workspace tests/doctests, Clippy, the supported feature matrix, WASM library checks, TypeScript build, and generated parity. Keep GPU resize and benchmarks in a separately labelled hardware/performance job. |
| Medium | MSRV is unspecified. The workspace sets version, edition, and license but no `rust-version` (`Cargo.toml:17-20`); every member inherits only those fields (`crates/mui/Cargo.toml:1-5` is representative), and there is no `rust-toolchain` file. `cargo metadata --no-deps --locked` reports `rust_version` as unset for all 11 packages. Current stable therefore defines the accidental support floor, while Clippy/rustfmt behavior can drift. | Choose and declare an MSRV, preferably centrally with `rust-version.workspace = true` in members, then test that toolchain plus current stable. Pin or otherwise document the formatter/linter toolchain used by CI. Edition 2021 is explicit and good; it should remain separate from the MSRV policy. |
| Medium | The local gate does not exercise the facade’s optional `egui` feature. `mui` defines `egui = ["dep:mui-egui"]` (`crates/mui/Cargo.toml:7-16`), but the default-feature commands in `tools/verify.sh:7-13` have no `--features`/`--all-features`. The targeted feature test passed in this audit, and the parent also passed the matching `mui --features egui` Clippy and WASM checks; this is therefore a gate omission only, not a current feature failure. | Add `cargo test -p mui --features egui --locked` and matching Clippy/WASM checks to CI. `--all-features` is suitable only when features are additive; retain targeted commands for mutually exclusive feature combinations. |
| Medium | WASM wording overstates the gate. `README.md:9` says the whole workspace, including egui, compiles to `wasm32-unknown-unknown`, and `README.md:457` calls it “full-workspace WASM compilation”; the actual default command excludes the native `mui-preview` binary (`tools/verify.sh:9-13`). The README explains the exclusion at `README.md:411-412`, and the parent separately passed the `mui --features egui` WASM check, so the implementation is intentional but the headline is still broader than the default script. | Say “all library crates, excluding the native preview host” and state that the `mui` facade’s `egui` feature is covered by a separate feature command. Keep the exclusion until a browser/canvas preview target exists. |
| Medium | The README’s TypeScript example is not compiled and has drifted from the public TS API. The prose says `packages/mui-ts/examples/pill.ts` is real TypeScript, but the snippet at `README.md:104-135` omits imports and uses `palette.accent`; `Palette` exposes `primary`, `secondary`, `tertiary`, `success`, `warning`, and `danger`, with no `accent` (`packages/mui-ts/src/index.ts:79-95`). The actual example imports helpers and uses `skin` (`packages/mui-ts/examples/pill.ts:1-9`, `packages/mui-ts/examples/skin.ts:8-15`). `tsc` includes source/examples, not README (`packages/mui-ts/tsconfig.json:9-13`). | Replace the prose block with an include/link to the real example, or extract it into a checked fixture. At minimum, change `accent` to the actual API and add imports. This is the clearest documentation correctness gap found. |
| Low | The facade says “Every `rust` block in the README” is compiled and run (`crates/mui/src/lib.rs:19-26`), and the roadmap repeats that every block runs under doctests (`ROADMAP.md:145-148`), but three Rust fences are explicitly `rust,ignore` (`README.md:40-53,347-349`). The baseline’s three ignored doctests correspond to those fragments. They are intentionally incomplete examples, but the wording implies stronger coverage than exists. | Reword to “every runnable Rust block” and explain why the three fragments are ignored, or turn them into complete doctests with hidden imports/setup. Current [rustdoc guidance](https://doc.rust-lang.org/rustdoc/documentation-tests.html) documents `ignore`/`ignore-*`, `no_run`, `compile_fail`, and `text`/`custom`; use `text` for illustrative fragments, and add hidden imports such as `# use example_crate::Token;` for runnable examples. `no_test` is not a documented replacement. |
| Medium | The TypeScript compiler has no unit-test script or test target (`packages/mui-ts/package.json:6-14`). The verification path compiles and generates one pill scene (`tools/verify.sh:15-23`), while the compiler contains unexercised branches for row/overlay nodes, max/grow/alignment/justification variants, radius/corner variants, outset surfaces, optional palette fields, and non-finite-number rejection (`packages/mui-ts/src/compiler.ts:10-78`). A single parity fixture cannot catch regressions in those branches. | Add a small `node:test` matrix after `tsc` (no new framework): compile representative scenes, assert generated Rust fragments, and assert `NaN`/infinite values fail. Include row, overlay, max/grow, all alignment/justify values, absolute/normalized radii, merge/inset/outset, and a sparse/default theme. |
| Low | `mui-egui::paint` is a public rendering seam (`crates/mui-egui/src/lib.rs:132-161`) but the egui tests cover preparation, transactional state, and cache invalidation only (`crates/mui-egui/src/lib.rs:164-236`). There is no assertion that mesh vertices receive the requested origin/fill or that a positive stroke emits the expected closed lines. | Add a lightweight egui context/painter test if this adapter remains supported; otherwise document that rendering is covered only through the preview/backend smoke path. |
| Low | `Tessellator::tessellate` has an explicit coordinate-overflow error branch (`crates/mui-tessellate/src/lib.rs:48-93`), but its two tests cover only a valid concave union and a hole (`crates/mui-tessellate/src/lib.rs:97-140`). Malformed/empty paths, non-finite converted coordinates, and flattening-budget errors are not directly locked down. | Add focused invalid-input tests before changing the error contract. This can remain a small unit matrix; no property-test framework is needed. |
| Low | Examples are compile smoke checks, not behavior checks. `mui-geometry/examples/offset_demo.rs:1-45` and `mui-layout/examples/pill.rs:1-24` only print results; the headless renderer writes a PNG but does not assert pixels (`crates/mui-vello/examples/headless.rs:62-101`). The verification script runs the demo binary but not these examples (`tools/verify.sh:18-24`). | Keep compile coverage as the default. Add assertions only where output is a documented contract, and reserve image comparison for the planned CPU/snapshot backend (`ROADMAP.md:221-223`). |
| Low | Cargo uses a committed lockfile (`Cargo.lock:1-3`), but every build/test/check/run command in `tools/verify.sh:7-24` omits `--locked`. A dependency resolution change can update the lockfile or fail differently from the parent baseline, weakening reproducibility. `npm ci` correctly enforces its lockfile. | Add `--locked` to Cargo commands in the gate and CI. Keep `--offline` only for an intentionally cached reproducibility mode; a clean CI job should fetch first, then run locked. |

## Coverage limits to keep explicit

The benchmark notes are unusually honest and should remain so: the raster check is a smoke test rather than a ground-truth or high-DPI comparison (`BENCHMARKS.md:53-54`), GPU execution is not identified (`BENCHMARKS.md:55-56`), and accessibility, keyboard traversal, and IME are incomplete (`BENCHMARKS.md:61`). The roadmap also explicitly defers CPU snapshot rendering and hot-reload/component testing (`ROADMAP.md:221-223,243-250`). These are product-scope limits, not regressions in the default test gate. A future hardware job and snapshot suite should be added when those claims become release requirements.
