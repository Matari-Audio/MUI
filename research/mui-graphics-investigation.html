Findings — expand for evidence

FIXED · P1Resize and outdated-surface recovery bypassed guarded configuration

Initialization used validation / out-of-memory / internal error scopes and caught configuration panics. Resize and outdated-surface recovery called surface.configure directly. Both now use the shared guarded helper. A failed configure returns a typed error; the stored configuration and size commit only after success. The plugin host also logged a failed resize and continued presenting, potentially clearing its pending redraw. It now skips that presentation and retries after 500 ms with the frame still pending.

crates/mui-vello/src/host.rs · configure, Host::resize, present_inner. Configuration has documented failure / panic conditions: wgpu Surface documentation.

FIXED · P1Renderer size changed before framebuffer allocation succeeded

GpuRenderer::resize set self.size before allocating a larger target. If that allocation panicked and an outer window guard caught it, a retry could compare equal and skip the allocation. The assignment now follows allocation. This fixes the stale-state path; it does not make all GPU allocation failures recoverable.

crates/mui-vello/src/effects/retained.rs:486

FIXED · P1A panicking plugin logger could escape the native callback guard

The guard caught a window callback panic, then invoked the plugin’s View::log outside the catch. A logger panic could cross the native boundary. Logging now catches that panic too and preserves the original and logger failure in MUI diagnostics. A regression test is added; its final execution is blocked.

crates/mui-baseview/src/lib.rs:843 · log, guard

PARTIAL · P1Fatal startup faults had no automatic durable report

New session journals record the last operation before driver entry. Retained reporters automatically queue caught errors, actual-device metadata and panics. Locked markers cover instance / surface creation, adapter enumeration, device / renderer startup, configuration and the first successful draw. After abrupt termination, the next load reports an unconfirmed interrupted operation. Normal return and Rust unwind clear the marker; live owners are skipped.

Steady-frame native faults, forced host termination and unrelated DAW crashes still require OS exception / stack evidence. This implementation does not install process-wide hooks or claim fault ownership. It is not a full minidump collector.

crates/mui-vello/src/diagnostics.rs and diagnostics/reporting.rs. OS file-lock release is documented in Rust File locking.

OPEN · P1Plugin pins and native fallback behavior differ

KORREKT’s pin contains native CPU fallback and deferred secondary-backend startup that are absent from this MUI checkout and the KONTRA / Relay pins. Opening all enabled backends can enter a failing driver before candidate fallback helps. Review and reconcile those existing changes before treating all released plugins as equivalent.

Existing MUI commits: native CPU fallback + deferred backend startup and preserved fallback diagnostics. These changes were inspected, not merged or released here.

RISK · P2Framebuffer retention can amplify memory pressure

The target is bounded by maximum texture dimensions, not a total byte budget. One 16,384 × 16,384 RGBA8 texture is 1 GiB, before other resources. Resize retains each dimension’s maximum: 8,192 × 512 followed by 512 × 8,192 retains an 8,192² target (256 MiB) for a current 16 MiB viewport. This is a source-level memory risk, not proof of the reported crashes.

crates/mui-vello/src/effects/retained.rs:269, :469, :486. Next: measure allocation pressure, then bound retained area / reclaim large targets and validate fallback under OOM.

OBSERVED · P2Relay requests a frame continuously

Relay’s .changed(|| true) keeps its editor drawing. That increases exposure to a rendering or driver failure and uses GPU time continuously. It does not establish that Relay currently crashes.

Relay worktree · plugin/src/ui.rs:200 · MuiEditor

OPEN · P2Linux XIM has unchecked input decoding and a discarded error

The vendored XIM client calls expect when decoding externally supplied compound text and discards handle_reset_ic’s Result. Those are real input-boundary / error-propagation weaknesses. They were not changed in this graphics patch and do not explain a Windows GPU report.

vendor/xim-rs/src/client.rs:144, :145, :205, :257

Integration and lifecycle

Enable mui/reporting; create Config with app version, app build and the actual MUI git pin; retain Reporter::start(config) on owned state. Close windows before dropping the last reporter, off the audio thread. Reporter setup failure can leave the editor usable.

The worker is joined before plugin unload. ureq’s default timeout resolver spawns a detached DNS thread, so the implementation reuses its resolver synchronously on the owned worker. HTTP is configured for five seconds, but OS DNS can delay shutdown longer. An external collector is the next step if bounded shutdown or full native dumps are required.

Local limits: 32 pending reports and 32 live / interrupted markers per app directory; admission uses an OS lock across processes. Session logs rotate at 1 MiB. Server recovery scans at most 500 authored issues / comments and preserves local evidence at that ceiling. GitHub + R2 delivery is not an exactly-once transaction.

Backend changes are in service worktree /tmp/mui-support-service-t3-5612c58a, branch feat/mui-automatic-reports. Configure GITHUB_MUI_TOKEN (or the existing support token with MUI permissions), MUI_REPORT_AUTHOR, and existing storage / rate-limit bindings. Production deployment and live issue creation await rollout.
